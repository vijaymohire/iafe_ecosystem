# 1. Purpose

This document provides a centralized catalog of repositories that collectively form the **IAFE (Intelligent Academy–Factory Ecosystem)**.

The objectives are to:

- Maintain a single source of truth for repositories.
- Document repository responsibilities.
- Define ownership and dependencies.
- Promote reuse.
- Simplify onboarding.
- Support release planning.
- Enable ecosystem-wide governance.

---

The IAFE ecosystem is organized into the following categories:

# 12. Repository Naming Convention

Repositories should use consistent naming.

Examples:

```
iafe-sdk

iafe-control-planes

iafe-app-healthcare

iafe-network

iafe-search

faep-education
```

Recommended prefixes:

- iafe-
- faep-
- qai-

---

# 13. Repository Ownership

Each repository should define:

- Repository Owner
- Technical Lead
- Maintainers
- Reviewers
- Contributors
- Release Manager

---

# 14. Dependency Management

Repositories should:

- Minimize dependencies.
- Reuse shared SDKs.
- Follow interface contracts.
- Avoid circular references.
- Remain independently buildable.
- Support semantic versioning.

---

# 15. Future Expansion

Additional repositories should align with the layered IAFE architecture and maintain consistency with existing engineering practices.

New repositories should be introduced only when they represent a distinct engineering responsibility or reusable capability.
